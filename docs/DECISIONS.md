# 결정이 필요한 것들

이 문서는 **코드를 만지지 않는 사람**(기획/제품 책임자)이 읽는 문서입니다.
"어떻게 고칠까"가 아니라 "어느 쪽으로 갈까"만 모았습니다. 각 항목에
번호가 있으니, 결정했으면 "3번은 B로 해줘"처럼 번호로 알려주면 됩니다.

기술적인 근거나 코드 위치가 더 필요하면 괄호 안 문서를 참고하세요
(`docs/UI/15-수정-내역.md`, `docs/UI/16-원본기획서-대조.md`).

마지막 정리일: 2026-08-05

## 🔴 지금 판단이 필요한 것 (안전/법적 영향)

### 1. 미성년자에게 술 메뉴를 그대로 보여줘도 되나요?

지금은 가입할 때 생년월일을 받기만 하고 **어디에도 쓰지 않습니다.** 나이와
상관없이 모든 사용자에게 주류 메뉴가 그대로 보입니다.

- **A. 지금 그대로 둔다** — 아무 조치 안 함
- **B. 생년월일로 19세 미만이면 주류 카테고리만 숨긴다** — 이미 받고 있는
  정보로 화면만 가리는 것이라 비교적 간단
- **C. 더 확실한 성인 인증(본인인증 API 등)을 새로 붙인다** — 비용·개발
  기간이 늚

*참고: `docs/UI/16-원본기획서-대조.md` B-5*

## 🟡 서비스의 핵심 방향에 관한 것

### 2. 캘린더를 "비공개/공개"로 나눌 건가요?

원래 기획서에는 "내 일정은 나만 보고, 친구에게는 빈 시간만 보여준다"는
분리가 핵심 기능으로 있었습니다. 지금 앱에는 이 구분이 없고, 메모 하나하나에
공개 범위(전체/베스트/나만)를 거는 방식만 있습니다.

- **A. 지금 방식 유지** — 메모 단위 공개 범위로 충분하다고 본다
- **B. 원래 기획대로 캘린더 자체를 비공개/공개로 나눈다** — 구조 변경이
  꽤 큼

*참고: `docs/UI/16-원본기획서-대조.md` B-2*

### 3. 방은 언제 자동으로 사라져야 하나요?

지금은 **방을 만든 시점**부터 24시간 뒤 자동 삭제됩니다. 원래 기획서는
**약속이 끝난 시점**부터 24시간(정산할 시간을 주는 목적)이었습니다.

지금 방식대로면, 다음 주 약속을 미리 잡아두면 **정산도 하기 전에 방이
사라질 수 있습니다.**

- **A. 지금 방식 유지** (방 생성 후 24시간)
- **B. 원래 기획대로 변경** (약속 종료 후 24시간)

*참고: `docs/UI/16-원본기획서-대조.md` B-1*

## 🟢 화면 재설계 때 없어진 정보, 되살릴까요?

한 번의 리디자인 작업(커밋 메시지엔 "improve"라고 돼 있음)에서 아래
정보들이 화면에서 빠졌습니다. 사라진 게 나은 것도, 원래대로가 나은 것도
섞여 있습니다.

| 정보 | 지금 상태 | 되살릴까요? |
|---|---|---|
| 채팅방 목록의 최근 메시지 미리보기 | 없음 | 되살리는 걸 권장 |
| 채팅방 목록의 초대 코드 표시 | 없음 | 되살리는 걸 권장(친구 초대 핵심 동선) |
| 프로필의 생년월일/계좌 표시 | 없음 | 되살리는 걸 권장(계좌는 정산에 필요) |
| 안 읽은 메시지 배지 | 있음 | 지금 그대로가 나음 |
| 방 카드 액션 버튼 3개 | 있음 | 지금 그대로가 나음 |

→ 표 전체를 한 번에 "A. 다 되살린다 / B. 표에 적힌 권장대로만 / C. 그대로 둔다" 중 골라도 됩니다.

*참고: `docs/UI/14-영상-현행코드-차이.md`*

## 🔵 급하지 않은 것 (나중에 정해도 됨)

### 4. 안 쓰는 옛날 취향 게임 컴포넌트(`TastePicker.tsx`), 지울까요?

지금 화면 어디서도 안 쓰입니다. 원래 기획서의 "면 vs 밥" 방식 게임이
지금의 카드 스와이프 게임으로 바뀌면서 남은 잔재입니다.

- **A. 그냥 지운다**
- **B. "면 vs 밥" 축을 살려서 지금 스와이프 게임에 문항으로 추가한다**

*참고: `docs/UI/16-원본기획서-대조.md` A-1*

### 5. 내부 데이터 이름 하나(`alcoholLiquor`)를 다른 것들과 맞출까요?

다른 데이터 이름은 전부 `bank_account`, `health_issues`처럼 밑줄 표기인데
이것만 `alcoholLiquor`(낙타 표기)입니다. 동작에는 지장 없고, 코드 일관성
문제일 뿐입니다.

- **A. 지금 그대로 둔다**
- **B. `alcohol_liquor`로 통일한다**

### 6. 카카오/애플 소셜 로그인을 추가할까요?

지금은 이메일 가입만 있습니다. 카카오뱅크 계좌를 다루는 한국 서비스인데
카카오 로그인이 없다는 점은 짚어둘 만합니다. 급한 건 아닙니다.

### 7. 에브리타임(대학생 시간표 앱) 연동을 만들까요?

원래 기획서에 "검토" 정도로만 적혀 있던 항목입니다. 안 만들어도 문제
없습니다.

### 8. `App.tsx`의 오래된 리팩터링 뼈대, 마무리·정리·그대로 중 뭘 할까요?

과거에 상태 관리를 `App.tsx` 하나에서 여러 Context로 옮기는 작업이
시작만 되고 끝나지 않았습니다. 지금은 아무 문제 없이 동작합니다(껍데기만
있고 실제로 안 쓰여서 마운트 비용 정도만 더 듭니다).

- **A. 마저 옮긴다** — 코드가 깔끔해지지만 작업량이 큼
- **B. 안 쓰는 뼈대를 걷어낸다** — `App.tsx`가 단순해짐, 되돌리기 쉬움
- **C. 그대로 둔다** — 지금도 동작에는 지장 없음

*참고: `docs/UI/15-수정-내역.md` L-1*
