# 11. 지도 위치 지정

지도를 움직여 **화면 중앙 고정 핀**에 위치를 맞추는 방식의 좌표 선택 화면.

- **구현**: `ProfileSetup.tsx:2371` 부근, `LocationContext.tsx`
- **영상 근거**: t=219s

## 진입 경로

1. 설정 → 프로필 편집 → `기본 출발 위치` → `[📍 좌표 지정]` → `🗺️ 지도에서 직접 지정`
2. 방 생성 모달(03) → `[🗺 지도에서 위치 선택]`
3. 방 상세정보 모달(05) → 약속 장소 설정 (추정, 영상 미확인)

`ProfileSetup.tsx:150`의 `mapTargetField: 'startLocation' | 'preferredLocation'` 로 대상 필드를 구분합니다.

## 확정 처리

`[이 위치로 설정하기]` → Alert

```

지도의 선택 위치(동아대학교 승학캠퍼스)로
        설정되었습니다!

```

- **핀 위치에 해당하는 장소명을 역지오코딩해서 Alert 문구에 넣어줌**
- 저장 결과 (프로필 출발지의 경우):
  - `start_location_name` = `동아대학교 승학캠퍼스`
  - `start_latitude` / `start_longitude` = 핀 좌표
  - 프로필 폼의 `기본 출발 위치` 입력창과 그 아래 `위도: 35.1176  경도: 128.9680` 표시가 갱신됨
- `hasCompletedLocationTutorial = true` → 계정 완성하기 2단계 완료

## 코드에서 확인한 상세

### 대상 필드 구분 (`mapTargetField`, `ProfileSetup.tsx:150`)

```ts
const [mapTargetField, setMapTargetField] =
  useState<'startLocation' | 'preferredLocation'>('startLocation');
```

같은 지도 화면을 두 용도로 재사용합니다.

| 값 | 저장 대상 | 모델 필드 |
|---|---|---|
| `'startLocation'` | 기본 출발 위치 | `start_location_name` / `start_latitude` / `start_longitude` |
| `'preferredLocation'` | 선호 지역 | `personal_data.preferred_location` |

⚠️ `preferred_location`은 `PersonalData`에 선언되어 있지만(`types.ts:20`) **이 값을 읽는 곳을 찾지 못했습니다.** AI 추천에는 `start_*`만 쓰입니다. 선호 지역 설정 UI 자체도 영상에 없어, 미완성 기능으로 보입니다.

### CTA 버튼 (`ProfileSetup.tsx:2371`)

```tsx
<Text style={{ color: '#ffffff', fontSize: 13, fontWeight: 'bold' }}>
  이 위치로 설정하기
</Text>
```

`mapTargetField`와 무관하게 **버튼 라벨과 안내 문구가 동일**합니다. 즉 선호 지역을 고를 때도 `출발지로 지정됩니다`라고 표시됩니다 → 문구 분기 필요.

### 좌표가 실제로 쓰이는 계산

```ts
// ScheduleGrid.tsx:801 — 중간 지점 계산
const lat = p.start_latitude || 37.5665;   // 미설정 시 서울시청
const lng = p.start_longitude || 126.9780;
```

**출발지를 설정하지 않으면 서울시청으로 취급**되어 중간 지점 계산이 왜곡됩니다. 01 문서의 강남역 문제가 여기서 비롯됩니다.

→ 이 화면은 단순한 부가 설정이 아니라 **AI 추천 품질을 좌우하는 필수 입력**입니다. `계정 완성하기` 2단계에 배치한 것은 타당하나, 미설정 상태에서 중간 지점 추천이 그럴듯한 오답을 내는 것이 문제입니다.

## 🔴 Android에서 지도 기능 전체가 사용 불가 (실기기 확인)

`🗺️ 지도에서 직접 지정`을 선택하면 **앱이 즉시 크래시**합니다.

```
java.lang.IllegalStateException: API key not found.
  at com.google.android.gms.maps.MapView.onCreate(...)
  at com.rnmaps.maps.MapView.<init>(MapView.java:180)
  at com.rnmaps.maps.MapManager.createViewInstance(...)
```

### 원인

`react-native-maps`는 Android에서 **Google Maps SDK**를 사용하므로 API 키가 필요합니다.
그런데 `app.json`에 설정이 없습니다.

```jsonc
// app.json (현재)
"android": {
  "package": "com.mealchat.app",
  "adaptiveIcon": {...},
  "permissions": [...]
  // ❌ config.googleMaps.apiKey 없음
}
```

결과적으로 생성된 `AndroidManifest.xml`에도 `com.google.android.geo.API_KEY` 메타데이터가 없어,
`MapView`가 만들어지는 순간 예외가 던져집니다.

### 영상에서 문제없던 이유

**시연 영상은 iOS**입니다. iOS의 `react-native-maps`는 **Apple Maps**를 쓰기 때문에
API 키가 필요 없습니다. 영상 t=219s에서 지도가 정상 동작한 것은 그래서입니다.

→ **플랫폼 차이로 Android에서만 터지는 문제**이며, 영상만 봐서는 발견할 수 없었습니다.

### 영향 범위

`MapView`를 쓰는 3곳 모두 Android에서 크래시합니다.

| 위치 | 화면 |
|---|---|
| `ProfileSetup.tsx:2256` | 프로필 출발지 좌표 지정 |
| `ScheduleGrid.tsx:4785` | 방 생성 시 `🗺 지도에서 위치 선택` |
| 방 상세 장소 설정 | 05 문서 |

출발지 좌표는 **AI 중간 지점·이동 시간 계산의 입력**이므로([01](01-일정조율-탭.md) 이슈 #1),
이 기능이 막히면 `📍 현재 내 위치 (GPS)` 경로로만 좌표를 넣을 수 있습니다.

### 해결 방법 (미적용 — 키 발급 필요)

1. Google Cloud Console에서 **Maps SDK for Android** 활성화 후 API 키 발급
2. `app.json`에 추가

```jsonc
"android": {
  "config": {
    "googleMaps": { "apiKey": "AIza..." }
  }
}
```

3. `npx expo prebuild --platform android` 재실행 (매니페스트에 키 주입)

> 키는 `EXPO_PUBLIC_` 환경변수로 빼도 번들에 노출되므로, **Google Cloud에서 패키지명
> (`com.mealchat.app`) + SHA-1 인증서 지문으로 키 사용을 제한**하는 것이 표준 대응입니다.

## 여전히 미확인

- 지도 검색창 / 줌 컨트롤 / 현재 위치 버튼 존재 여부 (영상에서는 드래그만 확인)
- 위치 권한 거부 시 처리 — `📍 현재 내 위치 (GPS)` 경로의 권한 흐름
- 역지오코딩 실패 시 표시 문구 (성공 시 `지도의 선택 위치({장소명})로 설정되었습니다!`)
- 방 생성(03) / 방 상세(05)에서 지도를 여는 경로가 이 컴포넌트를 재사용하는지, 별도 구현인지
- **Android 지도 화면 자체** — API 키가 없어 렌더 불가
