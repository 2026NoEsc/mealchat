## 화면별 차이 상세

### 02 방 목록 카드 — 전면 교체

**영상 (초기 커밋, App.tsx 인라인)**
```
┌────────────────────────────────────────┐
│ 안녕                                   │
│ 모임기준일: 2026-07-25         입장 →  │
│ [emoticon:welling_eat]                 │
│ 방금                                   │
│ [일정 조율 중 🗓]  [코드: VF4HLD]       │
└────────────────────────────────────────┘
```

**HEAD (`RoomCard.tsx`)**
```
┌────────────────────────────────────────┐
│ [진행중]  안녕                    (3)  │  ← 상태 배지 + 미읽 카운트
│ 07.25.(토) • 2명 참여                  │
│ ───────────────────────────────────── │
│   💬 채팅      🍽 메뉴      📅 일정    │  ← 액션 3버튼
└────────────────────────────────────────┘
```

| 항목 | 영상 | HEAD |
|---|---|---|
| 상태 배지 | `일정 조율 중 🗓` / `확정: 7월 25일 (토) 17:00` | `진행중` / `확정됨` |
| 좌측 라인 색 | `Room.color` | `is_confirmed ? confirmed(보라) : menuNeeded(주황)` |
| 날짜 | `모임기준일: 2026-07-25` | `07.25.(토)` (`toLocaleDateString('ko-KR')`) |
| 최근 메시지 | 표시 (`[emoticon:...]` 원시 코드) | **제거됨** |
| 초대 코드 배지 | `코드: VF4HLD` | **제거됨** |
| 미읽 배지 | 없음 | 빨간 원형 카운트 (`unreadBadge`) |
| 진입 | `입장 →` 1개 | 카드 전체 + `채팅`/`메뉴`/`일정` 3개 |

> HEAD의 `채팅`/`메뉴`/`일정` 버튼이 **13 문서의 메뉴 화면으로 가는 유일한 경로**입니다 (`onMenuPress` → `setRoomSubTab('menu')`).
> 영상 시점에는 이 버튼이 없어 메뉴 화면에 도달할 수 없었습니다.

`RoomCard.tsx:22`에 미해결 TODO가 남아 있습니다.
```ts
// 메뉴가 미선정이면 주황색
// TODO: 메뉴 선정 여부 판단 로직 추가 필요
return THEME.menuNeeded;
```
→ 확정되지 않은 방은 메뉴 선정 여부와 무관하게 항상 주황색입니다.

## 복원 시 판단이 필요한 지점

리디자인 12커밋이 **커밋 메시지상 "improve"이지만 실제로는 정보를 덜어낸** 부분이 있습니다. 어느 쪽을 정본으로 삼을지 결정이 필요합니다.

| 항목 | 영상(구) | HEAD(신) | 의견 |
|---|---|---|---|
| 방 카드 최근 메시지 | 있음 | 없음 | 채팅 목록으로서는 있는 편이 유용 |
| 방 카드 초대 코드 | 있음 | 없음 | 코드 공유가 핵심 동선이라 노출 유지 권장 |
| 방 카드 미읽 배지 | 없음 | 있음 | 신규 쪽이 나음 |
| 방 카드 액션 버튼 | 없음 | 3개 | 신규 쪽이 나음 (메뉴 화면 진입 경로) |
| 프로필 생년월일/계좌 표시 | 있음 | 없음 | 계좌는 정산에 필요 — 노출 유지 권장 |
| 정산 카드 색상 | 흰색 | 상태별 컬러 | 신규 쪽이 상태 파악에 유리 |

**권장**: 신규 레이아웃을 기준으로 하되, 구버전에서 사라진 정보(최근 메시지·초대 코드·계좌)를 다시 넣는 방향.
