# 02. 채팅 탭 (방 목록)

하단 탭바 우측 `✨ 채팅` 활성 상태. 참여 중인 밀챗 방을 나열하고 입장하는 허브.

- **상태**: `activeTab === 'addons'` (`NavigationContext`)
- **구현**: `App.tsx:3293~3990`, 카드는 `RoomCard.tsx`
- **영상 근거**: t=1.5s(빈 상태), 44s, 48s, 112s, 154s(로딩), 165s, 168s, 175s

## 레이아웃

### 1. 앱 헤더

```
🎨 밀챗              [＋ 방만들기]   🔔    ⚙️

- 누르면 03 문서의 새 밀챗 방 만들기 모달 오픈 (`setShowCreateModal(true)`)

### 2. 섹션 제목

```

### 3. 초대 코드 입장

### 5. 방 목록 카드 (`RoomCard.tsx`)

```
┌────────────────────────────────────────┐
│ 안녕                                   │
│ 모임기준일: 2026-07-25         입장 →  │
│ 안녕                                   │
│ 3분 전                                 │
│ [확정: 2026-07-25 16:30] [코드: VF4HLD] │
└────────────────────────────────────────┘
```

카드 구성 요소:

| 요소 | 내용 | 비고 |
|---|---|---|
| 제목 | `Room.title` | 예: `안녕`, `아아` |
| 모임기준일 | `모임기준일: YYYY-MM-DD` | `Room.meeting_date` |
| 최근 메시지 | 마지막 `Message.message` | 이모티콘은 `[emoticon:welling_eat]` 원시 문자열로 노출 |
| 상대 시각 | `3분 전`, `14시간 전` | |
| 확정 배지 | `확정: 2026-07-25 16:30` (녹색) | `is_confirmed`일 때만 |
| 코드 배지 | `코드: VF4HLD` (노랑) | |
| 입장 버튼 | `입장 →` | 우측 정렬 |

- 좌측 세로 라인 색상 = `Room.color` (테마 색상)
- ⚠️ **이슈**: 최근 메시지 미리보기에 이모티콘 코드가 그대로 노출됨 (`[emoticon:welling_eat]`). 이모티콘 전송 시 `이모티콘을 보냈습니다` 같은 사람이 읽을 수 있는 문구로 치환 필요

## ⚠️ 이 문서의 방 카드는 현행 코드와 다릅니다

위에 기술한 카드는 **영상 시점(초기 커밋)의 UI**입니다. 현재 `HEAD`는 `RoomCard.tsx`로 교체되어 모양이 완전히 다릅니다.
차이 비교는 **[14 문서](14-영상-현행코드-차이.md)** 를 보세요. 요약:

- `모임기준일:` → `07.25.(토) • 2명 참여`
- `일정 조율 중 🗓` / `확정: ...` → `진행중` / `확정됨` 배지
- 최근 메시지·초대 코드 배지 **삭제됨**
- 미읽 카운트 배지 **추가됨**
- `입장 →` 1개 → `💬 채팅` / `🍽 메뉴` / `📅 일정` 3버튼

`🍽 메뉴` 버튼이 13 문서의 메뉴 화면으로 가는 유일한 경로입니다.

## 코드에서 확인한 상세 (영상 미노출분)

### 초대 코드 입력 검증

`TextInput`에 `autoCapitalize="characters"`, `maxLength={6}` — 소문자로 입력해도 자동 대문자화됩니다.

실패 시 Alert (`App.tsx:431~480`, `1595~1625`):

| 상황 | 제목 | 본문 |
|---|---|---|
| 코드 형식 불일치 | `오류` | `유효하지 않은 초대 코드입니다.` |
| 딥링크 경유 | `오류` | `유효하지 않은 초대 코드입니다. 초대 링크를 다시 확인해주세요.` |
| DB에 방 없음 | `오류` | `방을 찾을 수 없습니다.` |
| DB에 방 없음(딥링크) | `오류` | `방을 찾을 수 없습니다. 초대 코드가 정확한지 확인해주세요.` |
| **만료된 방** | `만료` | `방이 만료되었습니다.` |
| 프로필 미로드 | `오류` | `프로필 정보를 불러올 수 없습니다.` |
| 참여 상태 확인 실패 | `오류` | `참여 상태 확인 중 오류가 발생했습니다.` |
| 네트워크 | `연결 실패` | `네트워크에 연결할 수 없습니다. 인터넷 설정을 확인하고 다시 시도해 주세요.` |

입장 처리는 **4단계 검증**을 순서대로 수행합니다: ① 코드 형식 → ② 방 존재 → ③ 만료 여부(`expires_at < now`) → ④ 중복 입장 방지.

딥링크(`exp://.../--/join/{CODE}`)로 들어온 경우 로그인 전이면 코드를 보류했다가 **로그인 성공 후 재검증하여 자동 입장**합니다 (`App.tsx:645`).

## 여전히 미확인

- 방 목록 정렬 기준 — `roomList`를 만드는 `fetchRooms()`의 `order()` 절 미확인 (영상에서는 최근 활동 순으로 보임)
- 방 카드 스와이프/롱프레스 액션 — `RoomCard.tsx`에 `onLongPress` 없음. **존재하지 않는 것으로 확인됨**
- 만료 임박 방의 목록 내 시각적 표현 (만료된 방이 목록에서 사라지는지, 회색 처리되는지)
- 미읽 카운트 산출식 — `appNotifications.filter(n => n.room_id === room.id).length`로 계산하는데, `AppNotification`은 정산 알림 위주라 **채팅 미읽 수와 무관**할 가능성 (`App.tsx:3995`)
