# 03. 방 생성 및 입장

`새 밀챗 방 만들기` 모달과 개설 완료 처리.

- **상태**: `showCreateModal` (`NavigationContext`), `RoomCreationContext`
- **구현**: `ScheduleGrid.tsx:4516`
- **영상 근거**: t=4.25s(개설 완료), 274s(입력 중), 276s(개설 완료)

## 진입 경로

1. 채팅 탭 헤더의 `＋ 방만들기`
2. 일정 조율 탭의 `N월 N일로 약속 방 개설하기 🚀` — 이 경우 **약속 시작일이 미리 채워진 채로** 열림

## 개설 완료 처리

개설 직후 네이티브 Alert 표시. 영상에서 **두 가지 문구**가 확인됨:

```
┌─────────────────────────────┐        ┌─────────────────────────────┐
│        방 개설 완료          │        │        방 개설 완료          │
│                             │        │                             │
│ 초대코드: VF4HLD            │        │ 약속 조율 방이 생성되었습니다! │
│ 스마트폰 캘린더에도 자동 저장 │        │ 초대코드: V5L3QS            │
│ 되었습니다.                  │        │                             │
│           OK                │        │           OK                │
└─────────────────────────────┘        └─────────────────────────────┘
        (t=4.25s)                              (t=276s)
```

- **초대코드는 6자리 대문자 영숫자**로 서버 생성 (`Room.code`)
- 첫 번째 문구에만 `스마트폰 캘린더에도 자동 저장되었습니다` 안내가 있음 → 문구 통일 필요
- OK 누르면 모달이 닫히고 **개설한 방의 채팅방(04)으로 자동 이동**

## 다른 사람이 입장했을 때

방에 참여자가 들어오면 **양쪽 화면에 서로 다른 피드백**이 나타납니다 (t=21.7s).

- 입장한 사람(우측 화면): Alert
  ```
        방 입장
  '안녕' 방으로 입장했습니다!
           OK
  ```
- 기존 멤버(좌측 화면): 인앱 푸시 배너
  ```
  👋 장님이 입장했습니다              지금
  "안녕" 방에 새로운 참여자가 들어왔습니다
  ```
- 동시에 방 헤더의 `멤버 1명` → `멤버 2명`으로 실시간 갱신

## 코드에서 확인한 상세 (영상 미노출분)

### 약속 장소 자동 입력

일정 조율 탭의 **AI 맞춤형 핫플레이스**에서 가게를 선택해 두면, 모달 B의 약속 장소 필드에 자동으로 채워집니다.

```
placeholder="예: 강남역 삼겹살집 🐷 (선택 시 자동 입력됨)"
```
(`ScheduleGrid.tsx:4556`, 선택 상태는 `coordinationRoomLocation`)

### 개설 알림 (`sendRoomCreatedNotification`, `notificationUtils.ts:117`)

```ts
title: title,
body: `"${roomTitle}" 방이 생성되었습니다. 초대코드: ${roomCode}`,
data: { type: 'room_created', roomCode }
```

- ⚠️ **이 알림은 탭해도 아무 동작이 없습니다.** `setupNotificationListeners`가 처리하는 타입은 `schedule_confirmed` / `room_participation` / `message` 뿐이라 `room_created`는 switch에서 누락 (12 문서 참조)

### 입장 알림 (`sendUserJoinedNotification`, `notificationUtils.ts:140`)

```ts
title: `👋 ${userName}님이 입장했습니다`,
body: `"${roomTitle}" 방에 새로운 참여자가 들어왔습니다`,
data: { type: 'user_joined' }
```

영상 t=21.7s의 배너와 정확히 일치합니다. 이 타입도 탭 핸들러가 없습니다.

### 방장 결정 규칙

```ts
const sorted = [...participants].sort((a, b) =>
  new Date(a.created_at).getTime() - new Date(b.created_at).getTime()
);
return sorted[0]?.profile_id || null;
```
(`App.tsx:274`)

`Room.owner_id`가 아니라 **참여자 중 `created_at`이 가장 이른 사람**을 방장으로 계산합니다. `owner_id` 필드가 `types.ts:69`에 정의되어 있는데도 사용하지 않아 **두 기준이 어긋날 수 있습니다** — 방장 위임(`handleTransferRoomOwnership`) 후 `created_at` 순서는 그대로이므로 위임이 반영되지 않을 위험. 복원 시 `owner_id` 단일 기준으로 통일 권장.
