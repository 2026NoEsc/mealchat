# 01. 일정 조율 탭 (홈)

앱 최초 진입 화면. 하단 탭바 좌측 `📅 일정 조율` 활성 상태.

- **상태**: `activeTab === 'schedule'` (`NavigationContext`)
- **구현**: `ScheduleGrid.tsx` 를 `isGlobal` 모드로 렌더 (방에 속하지 않은 전역 캘린더)
- **영상 근거**: t=0, 121s, 123s, 184s, 194s, 198s, 201s, 264s, 267s, 271s, 287s

## 목적

특정 방에 들어가기 전에, **내 일정을 등록하고 메이트를 골라 언제 만날지 후보 날짜를 뽑아내는** 화면입니다.
여기서 뽑은 날짜로 곧바로 약속 방을 개설하는 것이 주 동선입니다.


- 확정 약속 카드는 보라 계열 강조 (`confirmed` 토큰)
- **기기 일정**은 배지로 구분되며 읽기 전용
- 메모는 **`calendar_notes` 테이블**에 저장됩니다 (`ScheduleGrid.tsx:1941`)

  ⚠️ **정정**: 초판에 `RoomNote` 모델을 쓴다고 적었으나 사실이 아닙니다.
  `types.ts`의 `RoomNote` 인터페이스는 **어디서도 사용되지 않는 고아 타입**이고,
  실제 데이터는 `ScheduleGrid.tsx:919`에 지역 선언된 `CalendarNote` 인터페이스와
  `calendar_notes` 테이블을 씁니다. 스키마는 `supabase/schema.sql` 참조.

  | | `RoomNote` (미사용) | `calendar_notes` (실제) |
  |---|---|---|
  | 키 | `room_id`, `profile_id` | `profile_id`, `date` |
  | 시간 | 없음 | `time`, `end_time` |
  | 기간 | 없음 | `start_date`, `end_date` |
  | 기기 연동 | 없음 | `calendar_event_id` |

- 확정 약속 메모는 `calendar_notes`가 아니라 **`rooms.memo` / `rooms.memo_visibility` / `rooms.memo_author_id`** 컬럼에 직접 저장됩니다 (`ScheduleGrid.tsx:1721`)

### 캘린더 자동 연동 토글 (`handleToggleCalSyncSwitch`, `ScheduleGrid.tsx:1086`)

```ts
setIsCalSyncSwitchEnabled(value);
await storage.setItem('@meety_calendar_sync_enabled', value ? 'true' : 'false');
if (value) await syncNativeCalendar();
else       await handleDisconnectCalendar();
```

- ON → `expo-calendar`로 기기 캘린더를 읽어 그리드에 반영. OFF → 연동 해제
- 설정값은 `@meety_calendar_sync_enabled` 키로 로컬 영속화 (앱 재시작 시 유지)
- 스토리지 키 접두사가 `@meety_` — 앱명이 밀챗(MealChat)/Bob-yak인데 세 번째 이름이 섞여 있음
- `isConfirmed`이면 토글 자체가 렌더되지 않음 (`ScheduleGrid.tsx:3777`)
- 당겨서 새로고침(`onRefresh`) 시 연동 상태면 캘린더를 다시 동기화

### 중간 지점이 강남역으로 나온 원인 — 확인됨

`ScheduleGrid.tsx:801`

```ts
activeLocs.forEach(p => {
  const lat = p.start_latitude || 37.5665;   // ← 미설정이면 서울시청
  const lng = p.start_longitude || 126.9780;
  totalLat += lat; totalLng += lng; validCount++;
});
```

**출발지를 설정하지 않은 참여자는 서울시청 좌표로 취급됩니다.** 부산 사용자 1명 + 미설정 1명이면 중심점이 경남 내륙으로 끌려가고, 허브 목록에서 유클리드 최근접을 고르면 강남역이 서면역을 근소하게 이깁니다.

허브 목록은 12개 (서울 8 / 부산 4) — `ScheduleGrid.tsx:816`, `aiRecommender.ts:514`에 **중복 하드코딩**되어 있습니다.

```
강남역 홍대입구역 사당역 왕십리역 서울역 혜화역 건대입구역 신도림역
서면역 부산역 센텀시티역 해운대역
```

거리 계산도 하버사인이 아닌 **위경도 단순 유클리드 거리**(`Math.sqrt(dLat² + dLng²)`)라 위도에 따른 경도 축소를 반영하지 못합니다.

복원 시 수정 방향:
1. 좌표 미설정 참여자는 평균 계산에서 **제외**(현재는 서울시청으로 포함)
2. 전원 미설정이면 중간 지점 섹션 자체를 숨기고 출발지 설정을 유도
3. 허브 목록을 상수 모듈로 추출해 중복 제거
4. 거리 계산을 `getHaversineDistance()`로 통일 (`aiRecommender.ts:96`에 이미 구현되어 있음)
