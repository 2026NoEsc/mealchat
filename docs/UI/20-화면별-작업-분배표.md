# 20. 화면별 작업 분배표 (Figma 리디자인)

Figma 파일(`xBf3b09D6Bj1dTiCixt25e`, "Application UI" 페이지)의 프로토타입 연결까지 마친 상태를 기준으로, 실제 코드 리디자인을 나눠서 진행하기 위한 표다. 작업 방법은 `.claude/skills/figma-to-mealchat-screen/SKILL.md`를 따른다.

> **범위 제외**: `1_로그인`, `1_회원가입`, `1.5_취향게임`의 온보딩 진입부(카카오·Apple·Google 소셜로그인, 이메일 가입 4단계, 가입 중 취향게임 진입) — 기존 `AuthScreen.tsx`를 그대로 유지한다. 단, 취향게임 자체는 프로필 탭의 "게임 시작"에서도 재진입하는 기존 기능(`ProfileSetup.tsx`)이라 아래 표에 별도로 포함했다.

## 담당자 배정 기준

2인 분업, **파일 단위로 나눠서 충돌·의존성을 최소화**했다:

- **담당자 A** — `App.tsx` 및 그 인라인 로직 쪽: 네비게이션 통합, 홈, 채팅방 전체 (12개 항목)
- **담당자 B** — `ProfileSetup.tsx`/`ScheduleGrid.tsx` 쪽: 프로필, 일정 조율 전체 (11개 항목, "프로필을 탭으로 전환"은 A의 네비게이션 통합이 끝난 뒤 시작)

> **2026-08-13 변경**: 담당자 A 가 12개 항목을 끝낸 뒤 **B 범위까지 이어서 맡게 되었다.** 파일 분리로 인한 충돌 걱정은 더 이상 없다.

두 사람이 겹치는 파일이 거의 없어 병렬 작업 중 merge 충돌 위험이 낮다. 유일한 순서 의존성은 "네비게이션 4탭 통합"(A) → "프로필을 탭으로 전환"(B) 하나뿐.
