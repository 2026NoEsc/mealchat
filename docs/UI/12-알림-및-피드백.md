## 1. 인앱 푸시 배너

화면 최상단에서 내려오는 카드. 아이콘 + 제목 + 본문 + `지금`(상대 시각).

```
┌──────────────────────────────────────────┐
│ 🔔  👋 장님이 입장했습니다          지금  │
│     "안녕" 방에 새로운 참여자가 들어왔습니다 │
└──────────────────────────────────────────┘
```

| # | 제목 | 본문 | 발생 시점 |

### 관찰된 문제

- ⚠️ **제목 불일치**: 4·5번은 `📌 약속 상태 변경`, 6번은 `📌 약속 확정`. 같은 확정 이벤트인데 제목이 다름
- ⚠️ **날짜 포맷 불일치**: 4번 `2026-07-25 16:30` vs 6번 `7월 25일 (토) 17:00`
- ⚠️ **이모티콘 표기 불일치**: 푸시 배너(3번)에서는 `이모티콘을 보냈습니다: 남남 웰링 이모티콘`으로 사람이 읽을 수 있게 나오는데, **방 목록 카드(02)의 최근 메시지에는 `[emoticon:welling_eat]` 원시 코드가 그대로 노출**됨. 같은 변환 함수를 쓰도록 통일 필요

## 3. 에러 토스트

화면 하단의 어두운 배경 토스트. 우측 `×` 로 닫기.

```
┌──────────────────────────────────────────┐
│ ❗ Error scheduling reminder notificat… × │
└──────────────────────────────────────────┘
```

| 메시지 | 발생 시점 | 비고 |
|---|---|---|
| `Error scheduling reminder notificat...` | t=149s | 약속 확정 후 리마인더 예약 실패 |
| `Error sending unpaid bill notificatio...` | t=201s 이후 **여러 화면에서 반복** | 미납 정산 알림 발송 실패 |

### 심각도

- ⚠️ **영문 원문 에러가 그대로 사용자에게 노출**됨. 앱 전체가 한국어인데 이 부분만 개발용 메시지
- ⚠️ 텍스트가 잘려서(`notificat…`) 무슨 문제인지 알 수 없음
- ⚠️ `Error sending unpaid bill notification`은 프로필 설정, 취향 게임, 홈 등 **전혀 관련 없는 화면에서도 반복 노출**됨 → 백그라운드 폴링이 계속 실패하고 있다는 뜻
- 복원 시: ① 한국어 메시지로 교체 ② 사용자 행동과 무관한 백그라운드 실패는 토스트로 띄우지 않기 ③ 근본 원인(알림 발송 로직) 수정

## 알림 데이터 모델

```ts
interface AppNotification {
  id: string;
  room_id: string;
  title: string;
  message: string;
  bank_name: string;      // 정산 알림 전용
  account_number: string; // 정산 알림 전용

```

- ⚠️ 정산 전용 필드(`bank_name`/`account_number`/`amount`)가 **선택 필드가 아닌 필수 필드**로 선언되어 있음. 입장/메시지/확정 알림에는 의미 없는 값이 들어가야 함 → 알림 타입별 유니온으로 분리 권장

## 약속 리마인더 정책 (`scheduleConfirmedReminderNotification`, `notificationUtils.ts:164`)

## 에러 토스트의 정체 — 확인됨

영상 하단의 어두운 토스트는 앱이 만든 UI가 아니라 **Expo LogBox가 `console.error`를 잡아 띄운 것**입니다.

| 영상 토스트 | 소스 |
|---|---|
| `Error scheduling reminder notificat...` | `notificationUtils.ts:213` |
| `Error sending unpaid bill notificatio...` | `notificationUtils.ts:113` |

두 함수 모두 `try/catch`로 감싸고 `console.error`만 찍은 뒤 조용히 넘어갑니다.

```ts
} catch (error) {
  console.error('Error sending unpaid bill notification:', error);
}
```

즉 **기능은 실패했는데 사용자에게는 아무 안내가 없고, 대신 개발용 영문 로그가 화면에 뜨는** 상태입니다.

복원 시:
1. 근본 원인 수정 — 알림 권한 미허용이거나 `expo-notifications` 트리거 형식 문제일 가능성. `requestNotificationPermissions()`가 호출되는지 먼저 확인
2. 프로덕션 빌드에서는 LogBox가 뜨지 않으므로 **개발 중에만 보이는 증상**. 그렇다고 방치하면 알림이 조용히 안 가는 버그가 남음
3. 사용자 행동(정산 등록)에 직접 연결된 실패는 한국어 안내로 노출, 백그라운드 폴링 실패는 무음 처리

`Profile.push_token` 필드가 정의되어 있어 기기 푸시(백그라운드)도 지원하는 구조입니다.
다만 **토큰을 등록·갱신하는 코드는 `notificationUtils.ts`에 없습니다.** `requestNotificationPermissions()`는 권한만 요청하고 `getExpoPushTokenAsync()`를 호출하지 않습니다 → 서버 발신 푸시는 미구현일 가능성이 높습니다. 영상의 알림은 전부 `scheduleNotificationAsync({ trigger: { seconds: 1 } })`로 **로컬 기기에서 1초 뒤 띄운 것**입니다.

> 즉 영상에서 좌/우 화면이 서로 알림을 주고받는 것처럼 보인 장면은, 실시간 DB 구독으로 변화를 감지한 각 기기가 **자기 자신에게 로컬 알림을 띄운 결과**입니다. 서버 푸시가 아닙니다.
