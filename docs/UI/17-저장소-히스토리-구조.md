## ⚠️ 초판 서술 정정

[15 문서](15-수정-내역.md) 초판에 다음과 같이 적었습니다.

> ```
> feat/chat-n-vote      5 앞 / 13 뒤
> feat/usability-update 4 앞 / 13 뒤
> feat/meety-ui-updates 2 앞 / 13 뒤
> ```
> `feat/chat-n-vote`는 5커밋 앞서 있어 미병합 작업이 남아 있습니다.

**이 숫자들은 의미가 없습니다.** `git rev-list --count A..B`는 merge-base가 없으면 단순히 "B에만 있는 커밋 수"를 세는데, 두 히스토리가 무관하면 그건 "미병합 작업량"이 아니라 **"완전히 다른 프로젝트의 커밋 수"**입니다.

`types.ts:8`의 주석 `// New fields from feat/chat-n-vote`를 보고 "타입만 들어오고 구현은 브랜치에 남아있을 수 있다"고 추정했던 것도 **근거가 약했습니다.** 6월 계보에는 해당 구현이 없습니다(아래 참조).

## 실무적 의미

**1. 6월 계보는 코드 기반으로는 쓸 수 없습니다.**
영상의 기능 대부분이 없고, 아키텍처도 완전히 다릅니다(Expo Router vs 모놀리식).

**2. 다만 두 가지 자산이 있습니다.**
- **`Meety.md`** — 원본 기획서(PRD). 지금까지의 계획서가 전부 영상 역산 추정이었으므로, 의도를 확인할 유일한 1차 자료입니다 → [16 문서](16-원본기획서-대조.md)
- **아키텍처 참고** — `src/services/` 레이어 분리와 Expo Router 구조는, main의 `App.tsx` 6,049줄 모놀리식을 리팩터링할 때 참고할 만한 선례입니다. 같은 팀이 한 번 시도했던 구조입니다.

**3. `refactor/api-keys-config`는 별개로 검토 대상입니다.**
7월 계보에 속하고 main보다 1커밋 앞서며 뒤처지지 않았습니다(fast-forward 가능).
내용은 `src/constants/config.ts` 신설 + API 키 중앙화(+1,772/−1,731).
현재 하드코딩된 허브역 배열·API 키 산재 문제를 이미 손댔을 가능성이 있어, **개발 시작 전에 병합 여부를 결정하는 것이 좋습니다.**
