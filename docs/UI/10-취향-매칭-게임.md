# 10. 취향 매칭 게임

스와이프 게임으로 음식 취향을 수집해 추천 알고리즘에 반영하는 온보딩 플로우. 4단계.

- **상태**: `isSettingsGameActive` (`NavigationContext`)
- **구현**: `ProfileSetup.tsx:994~1200`, 데이터는 `constants/foodData.ts`
- **영상 근거**: t=243.9s, 246.5s, 248s, 254s, 256s

## 진입 경로

설정 홈(09)의 `계정 완성하기` → `3. 음식 취향 매칭` → `[게임 시작]` (재실행 시 `[다시하기]`)

```
[게임 시작]
   ↓
① 음식 선호도 매칭 (1/10 ~ 10/10)   ← 카드 스와이프

   ↓
```

### 데이터 소스 (`constants/foodData.ts`)

`POPULAR_FOODS` 30종 중 10개를 출제. 각 항목은 5개 특성 라벨을 가집니다.

```ts
interface FoodItem {
  id: string;
  name: string;
  emoji: string;
  labels: {
    meat?: boolean;      // 육류
    seafood?: boolean;   // 해산물
    spicy?: boolean;     // 매콤
    greasy?: boolean;    // 기름진
    clean?: boolean;     // 담백한
    allergens?: string[]; // wheat / dairy / seafood / crustaceans / peanuts
  };
}
```

예시:
| 음식 | 이모지 | 라벨 | 알레르겐 |
|---|---|---|---|
| 삼겹살 | 🥓 | meat, greasy | — |
| 초밥 | 🍣 | seafood, clean | seafood |
| 떡볶이 | 🍡 | spicy | wheat |
| 마라탕 | 🌶️ | meat, seafood, spicy, greasy | peanuts |
| 물냉면 | 🧊 | clean | wheat |

- 좋아요/싫어요 결과가 `personal_data.foodTasteScores` 5개 축(`meatScore`, `seafoodScore`, `spicyScore`, `greasyScore`, `cleanScore`)에 누적
- 좋아요한 항목은 `personal_data.preferredFoods`에 저장

## 점수 산식 (`saveTastePreferenceData`, `ProfileSetup.tsx:693~745`)

5개 축 모두 0에서 시작합니다.

### 1단계 — ① 카드 게임 반영

```
♥ 좋아요한 음식: 해당 라벨마다  +1
✕ 싫어요한 음식: 해당 라벨마다  -0.5
```

`POPULAR_FOODS`의 `labels`(meat/seafood/spicy/greasy/clean)를 그대로 축에 매핑합니다.
좋아요 가중치가 싫어요의 2배 — 긍정 신호를 더 크게 봅니다.

### 2단계 — ② 문답 반영 (가중치 큼)

| 문항 | 오른쪽 선택 | 왼쪽 선택 |
|---|---|---|
| 1 (해산물/육류) | `meat +3`, `seafood -1` | `seafood +3`, `meat -1` |
| 2 (기름진/깔끔) | `clean +3`, `greasy -1` | `greasy +3`, `clean -1` |
| 3 (매운맛) | `spicy +3` | **`spicy = -10`** (덮어쓰기) |

- 문답 1문항(±3)이 카드 3장(+1×3)과 맞먹는 가중치입니다
- 3번 문항 왼쪽은 **누적값을 무시하고 `-10`으로 강제 설정**합니다 (코드 주석 `// 맵찔이`). 카드에서 매운 음식을 아무리 좋아요해도 무효화됩니다 — 알레르기·못 먹는 음식에 준하는 하드 제약으로 취급

### 결과 요약 문구 (`ProfileSetup.tsx:795~810`)

점수를 비교해 사람이 읽을 수 있는 태그로 변환합니다.

```
meatScore > seafoodScore  → 육류 선호
seafoodScore > meatScore  → 해산물 선호
cleanScore > greasyScore  → 깔끔·담백 🥗
greasyScore > cleanScore  → 기름진 요리 🍔
spicyScore == -10         → 맵찔이 🧊
```

이 요약이 설정 홈 프로필 카드의 `음식 취향` 값이 됩니다 (`getFoodTasteSummary()`).

## ④ 제약 사항 선택지 — ⚠️ 실기기 확인 후 정정

**초판에 `ALLERGY_PRESETS` / `HEALTH_PRESETS` / `FOOD_PRESETS` 상수를 선택지로 기재했으나 틀렸습니다.**
세 상수는 **정의만 되어 있고 어디서도 사용되지 않습니다**(각각 파일 내 1회 = 정의 자신).

실제 화면은 `ProfileSetup.tsx`의 **인라인 한글 배열**을 렌더합니다.

| 아코디언 | 실제 선택지 (인라인 배열) | 위치 |
|---|---|---|
| 🥛 식품 알레르기 | 갑각류 · 견과류 · 메밀 · 밀 · 복숭아 · 우유 · 조개류 · 토마토 · 계란 (**9종**) | `1216행` |
| 🩺 건강상 지병 | 당뇨 · 고혈압 · 통풍 · 역류성식도염 · 만성 위염 · 고지혈증 (**6종**) | `1246행` |
| 🍏 못 먹는 음식 기피 | 오이 · 가지 · 고수 · 민트초코 · 파인애플 피자 · 당근 · 굴 · 마늘 · 양파 (**9종**) | `1276행` |

### 🔴 이 때문에 안심 지킴이는 여전히 동작하지 않습니다

저장되는 값이 **한글 라벨**입니다.

```json
"allergyFoods": ["갑각류"]
```

그런데 `MenuRecommendation`의 `MENU_POOL`과 `BaeminSurvey`의 `BAEMIN_FOOD_DB`는
**영문 코드**(`shellfish`, `gluten`, `peanuts`, `diabetes`…)로 매칭합니다.

```ts
{ name: '초밥 🍣', allergies: ['fish', 'shellfish'], ... }   // 영문 코드
```

`'갑각류' !== 'shellfish'` 이므로 **한 건도 매칭되지 않습니다.**

즉 [15 문서](15-수정-내역.md) L절에서 저장 경로를 연결했지만, **값 형식이 달라
안심 지킴이는 아직 무력한 상태**입니다.

### 해결 방향 (미적용)

셋 중 하나를 선택해야 합니다.

1. **인라인 배열을 `*_PRESETS` 상수로 교체** — id를 저장하고 라벨만 표시.
   가장 깔끔하지만 선택지 목록이 바뀝니다(9종 → 6종 등).
2. **`MENU_POOL` / `BAEMIN_FOOD_DB`를 한글 라벨로 변경** — 데이터 쪽을 맞춤.
   선택지는 유지되나 두 파일의 음식 데이터를 전부 수정해야 합니다.
3. **매핑 테이블 추가** — `'갑각류' → 'shellfish'` 변환 계층.
   기존 값 호환에 유리하나 새 항목(견과류·메밀·토마토·계란 등)은 대응 코드가 없습니다.

선택지 목록 자체가 제품 결정이라 임의로 적용하지 않았습니다.

## ⚠️ 알레르기 코드 체계가 두 벌입니다

같은 개념에 서로 다른 키를 쓰고 있어 **취향 게임에서 저장한 값이 메뉴 필터에 매칭되지 않습니다.**

| 개념 | `foodData.ts`의 `allergens` | `ProfileSetup` / `MenuRecommendation` / `BaeminSurvey` |
|---|---|---|
| 밀가루 | `wheat` | `gluten` |
| 갑각류 | `crustaceans` | `shellfish` |
| 생선·해산물 | `seafood` | `fish` |
| 땅콩 | `peanuts` | `peanuts` ✅ |
| 유제품 | `dairy` | `dairy` ✅ |
| 복숭아 | — | `peach` |

실제 저장값은 `ProfileSetup`의 `ALLERGY_PRESETS`(후자)이므로, **`foodData.ts`의 `allergens` 필드는 아무 데서도 소비되지 않는 고아 데이터**입니다. 복원 시 한쪽으로 통일 필요.

- `preferredFoods`는 표시 전용이라 id 대신 **음식 이름**으로 저장합니다
- 상세는 [15 문서](15-수정-내역.md) L절

⚠️ **다만 안심 지킴이는 아직 동작하지 않습니다.** 저장 값이 한글 라벨이고
메뉴 데이터는 영문 코드라 매칭되지 않습니다 → 아래 "④ 제약 사항 선택지" 참조.

## 🚨 저장되는 데이터 — 정정 (수정 전 기록)

**초판에서 이 게임이 주종·알레르기·지병·기피음식을 저장한다고 적었는데, 사실이 아닙니다.**
`onSave()` payload를 직접 확인한 결과(`ProfileSetup.tsx:763`, `916`), **③④단계에서 수집한 값은 어디에도 저장되지 않습니다.**

### 실제로 저장되는 것

```ts
await onSave(name, avatarColor, {
  birthdate, gender, bank_account, bio, travelTime,
  profileEmoji, profileBgColor,
  hasCompletedProfilePhotoTutorial,
  hasCompletedLocationTutorial,
  hasCompletedFoodTasteTutorial: true,
  foodTasteScores: scores        // ← 취향 관련은 이것뿐
}, userTag, avatarUrl, startLocationName, startLatitude, startLongitude);
```

### 저장되지 않는 것

| 수집 단계 | state 변수 | 대응 필드 | payload 포함 |
|---|---|---|---|
| ① ♥ 한 음식 | `likedFoods` | `preferredFoods` | ❌ |
| ③ 선호 주종 | `selectedLiquors` | `alcoholLiquor` | ❌ |
| ④ 식품 알레르기 | `selectedAllergies` | `allergyFoods` | ❌ |
| ④ 건강상 지병 | `selectedDiseases` | `chronicDiseases` | ❌ |
| ④ 기피 음식 | `selectedDislikes` | `customDislikedFoods` | ❌ |

이 state들은 **초기 로드(`initialData.personal_data.*`)에서 읽기만** 하고, 저장 경로가 없어 값이 늘 빈 배열입니다.

즉 게임 ③④단계는 **UI만 있고 아무 효과가 없습니다.**

### 파급 효과

### 이름이 두 벌인 문제도 여기서 비롯됨

`ProfileSetup`은 `allergyFoods`/`chronicDiseases`/`customDislikedFoods`로 **읽고**,
소비처(`MenuRecommendation`, `BaeminSurvey`, `App.tsx` 프로필 열람)는 `allergies`/`health_issues`/`likes`/`dislikes`로 **읽습니다.**

**양쪽 다 writer가 없어서** 지금까지 아무도 문제를 눈치채지 못한 상태입니다.

### 수정 방향 (미적용 — 결정 필요)

1. canonical 이름을 하나로 정합니다. `ProfileSetup`이 유일한 writer가 될 것이므로 **`ProfileSetup`쪽 이름**(`allergyFoods`, `chronicDiseases`, `customDislikedFoods`, `alcoholLiquor`)을 표준으로 삼는 것을 권장합니다
2. `onSave()` payload에 5개 필드를 추가합니다
3. 소비처 3곳의 `allergies` → `allergyFoods`, `health_issues` → `chronicDiseases`로 변경합니다
4. `preferredFoods`는 소비처가 없으므로, 메뉴 추천에 연결하거나 수집을 중단합니다

> 앱 동작이 바뀌는(현재 무력한 기능이 살아나는) 변경이라 임의로 적용하지 않았습니다.
> 타입 선언(`PersonalData`)에는 8개 필드를 모두 추가해 컴파일은 통과하도록 해뒀습니다.

### 태그 자동 발급

프로필에 `tag`가 없으면 저장 시 **100~999 사이 난수 3자리**를 발급합니다 (`ProfileSetup.tsx:750`).
```ts
userTag = Math.floor(100 + Math.random() * 900).toString();
```
⚠️ 중복 검사가 없습니다. 같은 닉네임 + 같은 태그 조합이 생기면 01 문서의 메이트 추가(닉네임+태그로 검색)가 오작동할 수 있습니다.

## 재사용 컴포넌트 (`TastePicker.tsx`, 165줄)

게임 화면이 아닌 **일반 취향 입력 폼**에서 쓰이는 프리미티브 2종:

- `SingleSelect<T>` — 세그먼티드 단일 선택 (예: 면 vs 밥)
- `MultiSelectChips<T>` — 칩 다중 선택 (예: 한/중/일/양식, 주류)

영상에서 이 컴포넌트가 직접 쓰인 화면은 확인되지 않았습니다. ③ 주종 설정은 리스트+체크 형태로, `MultiSelectChips`와 다른 UI입니다.

## 수집된 취향의 소비처

| 취향 데이터 | 쓰이는 곳 | 문서 |
|---|---|---|
| `alcoholLiquor` | AI 추천 장소를 `술집`/`카페`로 결정 | 07 |
| `allergies` / `health_issues` | 메뉴 룰렛의 `안심 지킴이` 자동 제외 | 13 |
| `allergies` / `health_issues` | HEAD 프로필 카드의 음식 취향 칩 | 09 |
| `foodTasteScores` | 프로필 카드 `음식 취향` 요약 문구 | 09 |
| `preferredFoods` | (소비처 미발견) | — |

⚠️ `preferredFoods`(①에서 좋아요한 음식 id 목록)는 저장만 되고 **읽는 곳을 찾지 못했습니다.** 메뉴 추천에 반영되어야 할 데이터로 보이는데 미연결 상태입니다.

## `TastePicker.tsx`의 사용처 — 없음

`SingleSelect` / `MultiSelectChips` 두 프리미티브를 export하지만 **`src/` 어디에서도 import하지 않습니다.** 165줄 전체가 사문화 상태입니다. 주석의 예시(`면 vs 밥`, `한/중/일/양식`)로 보아 지금의 스와이프 게임 이전 설계의 잔재로 추정됩니다.
