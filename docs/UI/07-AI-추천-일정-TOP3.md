## 카드 구성

### 순위 배지 / 적합도

| 순위 | 배지 색 | 카드 테두리 | 확정 버튼 |
|---|---|---|---|
| 1순위 | 보라 (`confirmed` `#9B59B6`) | 보라 2px | 보라 채움 |
| 2순위 | 파랑 | 기본 회색 | — (스크롤 필요, 영상 미확인) |
| 3순위 | 파랑 | 기본 회색 | — |

- 우상단 `적합도: 93점` — `AIRecommendation.score`
- 1·2순위가 동점(93점)일 때 참석 인원 수로 tie-break (`aiRecommender.ts:481`)

### 정보 행 4종

| 아이콘 | 라벨 | 값 예시 | 필드 |
|---|---|---|---|
| 👥 | 참석 현황 | `2명 / 2명 참석 가능` | `attendance_count` / `total_participants` |
| 🌦 | 날씨 예보 | `흐림 ☁ (강수확률 30%)` | `weather_status`, `precipitation_probability` |
| 🚗 | 이동 시간 | `평균 약 10분 소요` | `average_travel_time` |

- 날짜/시각은 `YYYY-MM-DD (HH:MM)` 형식으로 크게 표시
- 그 아래 `ai_reason` 한 줄 + `[AI 요약 ⓘ]` 배지 (예: `모두 모이기 편리한 황금 시간대`, `모두 모이기 편리한 황금 저녁`)

## 적합도 점수 산식 (`aiRecommender.ts:420~470`)

100점 만점, 4개 항목 합산 후 반올림.

| 항목 | 배점 | 계산 |
|---|---|---|
| 참석률 | 50점 | `(가능 인원 / 전체 인원) × 50` |
| 날씨 | 20점 | `weather.rating × 0.20` |
| 이동 편의 | 20점 | `mobilityRating × 0.20`. `mobilityRating = max(10, 100 - (clamp(평균이동시간-15, 0, 75) / 75) × 90)` |
| 선호 시간대 | 10점 | 아래 표 |

**선호 시간대 배점**

| 조건 | 점심(12~14시) | 저녁(18~21시) | 그 외 |
|---|---|---|---|
| 주말 | 10점 | 10점 | 7점 |
| 평일 | 6점 | 10점 | 3점 |

### 장소 종류 결정 (`aiRecommender.ts:485~499`)

참여자의 `personal_data.alcoholLiquor` 선택 여부로 집계:

- 주류를 선택한 인원 > 선택 안 한 인원 → **`술집`**
  - 사유 문구: `술을 선호하는 참여자가 많아 술집/이자카야/펍 선호`
- 그 외 → **`카페`**
  - 사유 문구: `술을 선호하지 않거나 카페 선호`

→ 10 문서(취향 매칭 게임)의 **선호하는 주종 설정**이 이 화면에 직접 연결됩니다.

## 코드에서 확인한 상세 (영상 미노출분)

### 날씨는 실제 API가 아닌 결정론적 시뮬레이션 — 확정

`getSimulatedWeather()` (`aiRecommender.ts:107`)

```ts
const seed = (dateStr.split('-').map(Number).reduce((a,b) => a+b, 0)
              + Math.floor(lat + lon)) % 100;
```

| seed | status | 강수확률(pop) | rating(점수 반영) |
|---|---|---|---|
| < 15 | `비 ☔` | 80% | 30 |
| < 30 | `흐림 ☁️` | 30% | 80 |
| ≥ 30 | `맑음 ☀️` | 10% | 100 |

- **날짜 문자열의 숫자 합 + 좌표 정수부**를 시드로 쓰는 가짜 예보입니다. 실제 기상 API 연동 없음
- 영상의 `흐림 ☁ (강수확률 30%)`는 seed가 15~29 구간에 떨어진 결과
- 강수확률이 10/30/80 세 값만 나오므로 **후보 간 날씨 변별력이 사실상 3단계**뿐
- 복원 시: 기상청 단기예보 API 또는 OpenWeather 연동으로 교체 필요. 화면에 `AI 요약`이라 표기하면서 시뮬레이션 값을 쓰는 것은 사용자 오인 소지

### 장소 추천은 카카오 로컬 API — 실제 연동

`fetchNearbyKakaoPlaces()` (`aiRecommender.ts:6`)

```
GET https://dapi.kakao.com/v2/local/search/keyword.json
    ?query={카페|술집}&x={lng}&y={lat}&radius=2000&sort=accuracy
Authorization: KakaoAK {EXPO_PUBLIC_KAKAO_REST_API_KEY}
```

- 반경 **2km**, 정확도 순
- 키가 없으면 **빈 배열 반환** → 장소 추천 블록이 통째로 사라짐
- 응답 매핑에서 대부분 필드가 **고정 문자열**입니다:
  ```ts
  business_hours: '정보 없음',
  menu: '대표 메뉴 정보 없음',
  price: '가격 정보 없음',
  ```
  즉 영상의 `영업시간: 09:00 ~ 22:00`, `대표 메뉴: 아메리카노, 조각케이크`, `평균 가격대: 아메리카노, 4,500원`은 **카카오 응답이 아니라 Gemini가 생성한 값**입니다 (`EXPO_PUBLIC_GEMINI_API_KEY` 사용). 그래서 `💰 평균 가격대`에 메뉴명이 섞여 들어간 것 — LLM 출력 파싱이 헐거운 문제
- `PlaceRecommendation`에 좌표 필드가 없어 05 문서의 `(위도: undefined, 경도: undefined)` 문제로 이어집니다. 카카오 응답에는 `x`/`y`가 있으므로 **매핑만 추가하면 해결**됩니다

### 방 좌표 폴백 3단계 (`aiRecommender.ts:502~537`)

`room.latitude`/`longitude`가 없으면:

1. `fetchCoordsByKakaoSearch(room.location_name)` — 카카오 키워드 검색 1건
2. 하드코딩 허브 12개 중 `location_name.includes(허브명)` 매칭
   ```
   강남역 홍대입구역 사당역 왕십리역 서울역 혜화역 건대입구역 신도림역
   서면역 부산역 센텀시티역 해운대역
   ```
3. **서울시청 `37.5665, 126.9780`**

또한 `room.location_name`이 없으면 기본값이 `'강남역'`입니다 (`aiRecommender.ts:502`).

같은 허브 배열이 `ScheduleGrid.tsx:816`에도 복붙되어 있습니다. 중간 지점이 강남역으로 나온 원인 분석은 [01 문서](01-일정조율-탭.md)에 정리했습니다.

### `술집` vs `카페` 판정에 쓰이는 필드

```ts
const liquors = p.personal_data?.alcoholLiquor || [];
```

⚠️ `alcoholLiquor`는 **`PersonalData` 인터페이스(`types.ts:1~26`)에 선언되어 있지 않습니다.** 취향 게임(10 문서)에서 저장은 하지만 타입에 없어 컴파일 타임 검증이 안 되는 상태 → `types.ts`에 `alcoholLiquor?: string[]` 추가 필요.
