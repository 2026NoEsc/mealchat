# 08. N빵 정산

모임 비용을 1/N로 나눠 송금 요청을 만들고, 누가 얼마를 보내야 하는지 집계하는 화면.

- **상태**: `roomOverlay === 'dutch'` (방 내부) / 전역 정산 대장 (`App.tsx:4683`)
- **구현**: `DutchPay.tsx` (2,227줄)
- **데이터 모델**: `DutchPayBill`, `DutchPayMember` (`types.ts:98~119`)
- **영상 근거**: t=160s, 165s, 168s, 175s, 264s, 267s, 271s

## 진입 경로

1. 채팅방(04) 서브탭 `💸 N빵 정산` → 방 단위 정산
2. 채팅 탭(02) `💸 나의 N빵 정산 대장` `[보기 →]` → **방을 나가거나 방이 폭파된 뒤에도** 남는 전역 정산 목록

> 핵심 컨셉: *"방이 폭파된 후에도 남아있는 미완료 정산 내역을 확인하고 송금할 수 있습니다."*
> 방은 24시간 만료되지만 **정산 내역은 영구 보존**됩니다.

## 실시간 정산 상계 현황

```
⚖️ 실시간 정산 상계 현황 (총 1건)
여러 건의 정산 요청을 상계하여 최종적으로 주고받을 금액만 보여드려요.
┌────────────────────────────────────────┐
│ Dlwials  →  장 (나)         국민은행    │
│ 100원                 5537010141930    │
└────────────────────────────────────────┘
```

- `DutchPay.tsx:1030` — 코드 주석에 `{/* PPT Slide 7: 정산 상계 로직 대시보드 */}`
- **"집계"가 아니라 "상계"(netting)** 입니다. 단순 합산이 아니라 서로 주고받을 금액을 **차감 정리**해 최종 송금만 남깁니다
- **송금자 → 수취인** 방향 명시, 본인은 `(나)`로 표기. 내가 관련된 건은 녹색 테두리로 강조
- 우측에 수취인 은행명 + 계좌번호

### 🔬 실기기 검증 결과 (2인 방)

`TestBill` / 30,000원 / 2명으로 등록했을 때 실제 화면입니다.

```
⚖️ 실시간 정산 상계 현황 (총 1건)
┌────────────────────────────────────────┐
│ Mate  →  Tester (나)        카카오뱅크  │
│ 15,000원                  1234567890   │
└────────────────────────────────────────┘
```

| 확인 항목 | 결과 |
|---|---|
| 1/N 계산 | 30,000 ÷ 2 = **15,000원** |
| 상계 방향 표기 | `송금자 → 수취인 (나)` |
| 수취 계좌 | 프로필 값 자동 반영 |
| DB 저장 | `dutch_pay_members.name = "Mate:15000"` — `이름:금액` 구조 확인 |
| 나눌 인원수 | 참여자 수(2)로 **자동 설정** |
| RLS | 채무자 B도 `dutch_pay_bills_select`로 조회 가능 (`is_bill_participant`) |

상세는 [15 문서](15-수정-내역.md) K-3 참조.

### 상계 계산 로직 (`calculateSettlements()`, `DutchPay.tsx:513`)

```
1. 참여자별 balance { paid: 0, owed: 0 } 초기화
2. 각 정산 건마다
   - 결제자(creator): paid += total_amount
                      owed += (total_amount - 멤버들이 낼 합계)   ← 결제자 본인 몫
   - 각 멤버:          owed += 본인 배분액
3. netBalance = paid - owed
4. 음수(빚진 사람) → 양수(받을 사람) 방향으로 매칭해 송금 목록 생성
```

여러 방·여러 건에 걸친 채권채무를 한 번에 상계하는 구조입니다.

### 처리 흐름

1. 영수증 사진 업로드 (`handlePickReceiptImage`) — 미등록 시 `알림 / 영수증 사진을 등록해 주세요.`
2. 자연어 지시어 입력 (선택)
3. `AI 분석 및 자동 매칭 시작 ✨` → 진행 상태를 단계별 텍스트로 표시
   - `📷 실시간 영수증 OCR 판독 중...`
   - (시뮬레이션 모드일 때) `📷 [시뮬레이션] 영수증 텍스트 OCR 판독 중...`
4. Gemini에 영수증 이미지 Base64 + 프롬프트 전송
   > *"당신은 영수증 OCR 및 더치페이 매칭 전문가입니다. 제공된 영수증 이미지에서 모든 개별 메뉴 품목(품목 이름, 가격)을 정확히 판독하여 추출하세요."*
5. 성공: `분석 완료 / AI가 영수증의 실제 항목과 자연어 분배를 성공적으로 매칭했습니다!`
   실패: `AI 분석 실패 / 영수증을 판독하는 데 실패했습니다. 일반 모드로 항목을 불러옵니다.`
6. 항목별로 먹은 사람을 터치해 수동 조정 → 저장 시 제목이 `[AI 영수증] {모임명}` 형식으로 생성됨

- 이미지 Base64 로드 실패 시: `영수증 이미지 Base64 데이터를 로드하지 못했습니다. 다시 촬영/등록해 주세요.`
- **시뮬레이션 폴백 경로가 있어** API 키가 없어도 데모가 가능한 구조

## 송금 완료 처리 (`handleConfirmDeposit`, `DutchPay.tsx:823`)

정산 카드를 펼치면 **내 역할에 따라 다른 패널**이 나옵니다.

### 결제자(채권자) 화면

```
👥 구성원 입금 현황 관리
┌────────────────────────────────────────┐
│ 철희 (100원)          ✓ 입금 확인됨     │
│ 영수 (100원)      미입금    [ 확인 ]    │
└────────────────────────────────────────┘
[ 🔔 미입금자에게 독촉 알림 전송 ]
```

- **입금 확인은 결제자가 수동으로 누릅니다** (`[확인]` → `is_completed = true`). 자동 감지 아님
- 전원 완료되면:
  ```
  정산 완료! 🎉
  '안녕' 정산이 모든 구성원에 의해 완료되어
  대장에서 폭파(자동 삭제)되었습니다!
  ```
  → **정산 건이 목록에서 삭제됩니다.** "영구 보존"이라는 안내 문구와 상충 — 미완료 건만 보존한다는 뜻으로 문구 수정 필요
- `독촉 알림 전송`은 `is_completed === false`인 멤버에게만 발송

### 채무자 화면

| 상태 | 표시 |
|---|---|
| 완료 | ✅ `정산 완료! 예금주가 입금을 확인했습니다.` |
| 대기 | ❗ `정산 대기 중 (아래 수단으로 송금해 주세요)` |
| 비대상 | ℹ️ (이 정산의 멤버가 아님) |

## 알림 문구 불일치 — 확인됨

영상의 정산 푸시는
```
[밀챗 N빵 정산] 안녕 💸
인당 100원 송금 요청이 도착했습니다. (국민은행 5537010141930)
```

그런데 `notificationUtils.sendUnpaidBillNotification` (`notificationUtils.ts:92`)은
```
💰 미정산 내역이 있습니다
{creditorName}님에게 {amount}원을 보내야 합니다
```

**서로 다른 문구입니다.** 즉 정산 알림 경로가 최소 2개 존재합니다 — `DutchPay.tsx`가 직접 만드는 것과 공용 유틸. 하나로 통합 필요.

영상 후반 반복 노출된 `Error sending unpaid bill notificatio...` 토스트는 `notificationUtils.ts:113`의 `console.error('Error sending unpaid bill notification:', error)`가 Expo LogBox에 잡힌 것입니다 (12 문서 참조).
